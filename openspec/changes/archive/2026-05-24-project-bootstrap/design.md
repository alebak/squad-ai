# Design: Project Bootstrap

## Technical Approach

Initialize Go module, lay out the 7-package directory structure, wire the Cobra CLI entry point, and implement only `squad version` with a table-driven test. Matches Approach 1 from exploration — zero speculative code.

## Architecture Decisions

| Decision | Choice | Alternatives Considered | Rationale |
|----------|--------|------------------------|-----------|
| Module path | `github.com/alebak/squad-ai` | — | Must match GitHub repo for `go install`. Verified in PRD. |
| Go version | `go 1.24` | 1.26 (system default) | 1.24+ per spec; lower version is more portable. System 1.26.3 compiles it fine. |
| Cobra wiring | Global `var rootCmd` + `init()` subcommand registration | Constructor-based `NewRootCmd()` | The "no globals" rule targets business logic. Cobra's `var rootCmd` is the idiomatic pattern across virtually all Go CLI projects (Hugo, Helm, etc). Tests mutate `rootCmd.SetOut()` which is safe sequentially. |
| Version source of truth | `rootCmd.Version = "0.1.0"` | Separate `const version = "0.1.0"` | Cobra's built-in `--version` flag reads `rootCmd.Version`. Using it directly avoids duplication. Both `squad version` and `squad --version` read the same field. |
| Output format | `squad version {version}` | Plain `{version}` only | Matches Cobra's default version template. Ensures `squad version` and `squad --version` produce identical output (per spec). |
| Test pattern | `rootCmd.SetOut(buf)` + `SetArgs(args)` + `Execute()` | `ExecuteC()` returning command | `Execute()` is simpler and sufficient: we only need the output string. The buffer captures everything. `ExecuteC` is only needed when you inspect the returned Command object. |

## Data Flow

```
main() → cli.Execute()
           └── rootCmd.Execute()
                 ├── args=["version"]  → versionCmd.Run
                 │                       └── fmt.Printf → os.Stdout
                 ├── args=["--version"] → Cobra version template
                 │                       └── rootCmd.Version → os.Stdout
                 └── args=[]            → Cobra help template
```

Both paths produce `squad version 0.1.0\n` on stdout. The `version` subcommand uses `cmd.Root().Name()` and `cmd.Root().Version` to match the template.

## Test Design

**File**: `internal/cli/version_test.go`

**Structure**: Table-driven with two rows.

```go
func TestVersionCommand_Output(t *testing.T) {
    tests := []struct {
        name string
        args []string
    }{
        {name: "subcommand", args: []string{"version"}},
        {name: "flag",       args: []string{"--version"}},
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            buf := new(bytes.Buffer)
            rootCmd.SetOut(buf)
            rootCmd.SetArgs(tt.args)
            err := rootCmd.Execute()
            assert.NoError(t, err)
            assert.Contains(t, buf.String(), "squad version 0.1.0")
        })
    }
}
```

**Pattern**: Capture stdout via `bytes.Buffer` set on `rootCmd.SetOut()`. `SetArgs` overrides os.Args for each test case. `require.NoError` on Execute, then `assert.Contains` on output. Tests run sequentially (shared `rootCmd`).
