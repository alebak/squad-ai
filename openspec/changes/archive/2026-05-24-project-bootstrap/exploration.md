## Exploration: Project Bootstrap — `go mod init`, directory structure, `squad version` command, and first test

### Current State

Greenfield Go project. Zero `.go` files exist. The project has:
- **PRD.md**: Full product spec (Cobra, Bubbletea, registry, installer, runtime detection)
- **AGENTS.md**: Go code standards (idiomatic Go, godoc, no globals, short functions, testify)
- **CONTRIBUTING.md**: Branch/conventional commit conventions, build instructions
- **openspec/config.yaml**: SDD init already configured project structure and rules
- **`.gitignore`**: Standard Go ignores (binaries, test artifacts, coverage)
- **Go 1.26.3** available on the system — above the 1.24+ minimum

No dependencies are initialized, no modules exist, no directory structure beyond `.github/` and docs.

### Affected Areas

- **`go.mod`**, **`go.sum`** — Module definition at `github.com/alebak/squad-ai`, lockfile
- **`cmd/squad/main.go`** — Entry point: `package main`, calls `cli.Execute()`
- **`internal/cli/root.go`** — Root Cobra command (`squad`)
- **`internal/cli/version.go`** — `squad version` subcommand
- **`internal/cli/version_test.go`** — First test, verifying version output
- **Directories**: `cmd/squad/`, `internal/cli/`, `internal/tui/`, `internal/registry/`, `internal/installer/`, `internal/config/`, `internal/runtime/`

### Approaches

1. **Bootstrap + version only** — `go mod init`, create all directories, implement only `squad version`, write one test
   - Pros: Minimal scope, concrete and testable, no speculative code, establishes the pattern for future commands
   - Cons: Root command does nothing beyond `--help` (no default behavior yet)
   - Effort: Low (~60 Go LOC across 4 files)

2. **Bootstrap + root command with placeholder** — Same as above, plus a placeholder root command that prints "Squad AI — agent manager" and exits
   - Pros: `squad` with no args does something visible
   - Cons: Placeholder creates throwaway code — root behavior will fundamentally change when TUI/config are added
   - Effort: Low (~70 LOC)

3. **Bootstrap + full skeleton** — Add all command stubs (`install`, `add`, `remove`, `list`, `info`, `update`, `version`) with "not implemented" messages
   - Pros: Complete command scaffolding upfront
   - Cons: Violates YAGNI — creates dead code that needs updating as each command is implemented; 7 stubs = ~150 LOC of unreachable code
   - Effort: Medium (~150 LOC)

### Recommendation

**Approach 1 — Bootstrap + version only.**

Reasons:
- Every new Go project starts with `go mod init`. This is the natural first commit.
- `squad version` is the simplest command with zero dependencies on other packages — no TUI, no registry, no config file. Pure Cobra wiring.
- It's fully testable (capture stdout, assert output matches `0.1.0`).
- It establishes the canonical patterns: Cobra command in `internal/cli/`, entry point in `cmd/squad/main.go`, test alongside the code.
- No dead code. Future commands will be added organically.
- The 400-line PR budget is easily respected (~60 lines of Go + go.mod).

What the root command should do:
- `cmd/squad/main.go` calls `cli.Execute()`
- `root.go` defines the root command with `Use: "squad"`, `Short: "Squad AI — AI coding agent manager"`, and adds the version subcommand
- `root.go` sets a `Version` field so Cobra's built-in `--version` flag works too
- No default behavior for `squad` with no args yet (that comes when config/registry/TUI are built)

Version value: `0.1.0` (matching PRD version).

### Risks

- **Module path must match the GitHub repo**: `github.com/alebak/squad-ai` — confirmed from PRD. If this doesn't match, `go install` and downstream consumption breaks. Mitigation: use exactly what's in the PRD.
- **Cobra dependency version**: Must pin a specific version in `go.mod`. Cobra v1.10.2 is latest and compatible. Use that.
- **No `go.sum` yet**: Generated by `go mod tidy` — need to run that before committing.
- **Test depends on Cobra's `ExecuteC`**: Need to test using `ExecuteC` which returns the cobra command (or capture rootCmd output) to verify version string. Standard pattern with Cobra's `cmd.SetOut()`.
